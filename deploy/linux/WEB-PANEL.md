# Greatness Bot — веб-админка

Сайт с админ-панелью работает внутри бота (тот же процесс, те же данные).
Бот слушает только `127.0.0.1:5080`, наружу сайт отдаёт **Caddy** с бесплатным HTTPS (Let's Encrypt).
Вход — через Discord. Владелец бота (`Bot:OwnerId` в `appsettings.json`) видит всё, остальным он выдаёт
доступ в разделе **Access** — по людям и по разделам.

Всё бесплатно: поддомен DuckDNS, сертификат, Caddy.

Разделы панели: **Overview**, **LFG** (активности, панель, активные группы), **Tickets** (проекты, роли, категория,
текст тикета, открытые тикеты), **Temp Voice** (каналы «join to create», панель, активные комнаты),
**Panel texts** (заголовок, текст и подписи кнопок панелей LFG / Tickets / Room controls — уже опубликованные
панели обновляются при сохранении), **Access** (только владелец: кому и какие разделы открыты).

### Доступ (раздел Access)

- Открыт только владельцу бота, выдать его нельзя.
- Человека можно выбрать из участников сервера или вставить его Discord ID.
- Разделы: LFG, Tickets, Temp Voice, Panel texts, Posts, Log, Settings — галочками. Overview видят все, у кого есть доступ.
- Права проверяются на каждый запрос: снятие доступа действует сразу, перелогиниваться не нужно.
- Хранится в `data/web-access.json`.

### Структура сайта: Member и Admin

**Member** — всем, у кого на сервере роль «участник» (Settings → Member roles). То же, что участник может в Discord:

| Вкладка | Что там |
| --- | --- |
| 🏠 Home | мои сборы (организатор / в группе / резерв), мои заявки (тикеты), моя голосовая комната (имя, лимит, закрыть/открыть) |
| 🎮 Groups | все активные сборы: записаться, сменить роль/персонажа, выйти; **создать сбор**; в своих сборах (организатор) — резерв туда-обратно и закрыть |
| 🧙 My characters | персонажи, класс-роль и заметка; ЛС о сборах вкл/выкл |

**Admin** — только владелец и те, кому он выдал права в **Access** (по разделам):

| Группа | Вкладки |
| --- | --- |
| Modules | 📣 LFG (активности, панель, повторяющиеся сборы, состав любого сбора, принудительное закрытие), 🎫 Tickets, 🔊 Temp Voice |
| Content | 📌 Panels & posts — тексты панелей (право Panel texts) и сообщения бота (право Posts) |
| System | 📊 Dashboard, 📜 Log, ⚙️ Settings, 🔑 Access (только владелец) |

Участнику без прав админ-разделы не видны, их API отвечает 403. Организатор может управлять только своими сборами.

### Новое: тикеты, LFG, комнаты, резервная копия

- **Анкета заявки** (Tickets → проект → Application form): включается для каждого проекта, до 5 вопросов
  (текст, подсказка, короткий/длинный ответ, обязательный, макс. длина). Окно в Discord перед созданием тикета или форма на сайте.
- **Deny** с причиной (уходит заявителю в ЛС), **архив** закрытых тикетов с поиском (`data/ticket-archive.json`),
  **авто-закрытие** неактивных тикетов через N дней (предупреждение за 24 ч), **заявка с сайта** (Home → Apply).
- **Шаблоны сборов** (LFG → Templates), **требования** (роль и/или минимальный GS; GS — `/character gs` или My characters),
  **перенос времени** (⚙️ Manage → Change time, сайт → 🕒 Time) с ЛС записавшимся, **явка** после старта и **статистика**
  (`data/lfg-history.json`), **🔊 Voice room** сбора: все слушают, говорят только участники группы.
- **Мои настройки комнаты** (Home или `/room defaults`).
- **💾 Backup** (Settings, только владелец): скачать `data/*.json` архивом или восстановить — бот перезапускается,
  текущие данные перед этим сохраняются в `data/backups/`.

### Проекты (игры), классы, дубли постов, голосовая комната по выбору

- **LFG → 🎮 Projects**: проект = игра (Aion 2, WWM…) + нужная роль. У каждого проекта свои персонажи; добавить/выбрать
  персонажа проекта и записаться в его сбор можно только с его ролью. Персонажи, созданные раньше, — в проекте **по умолчанию**.
  Каждую LFG-панель можно привязать к проекту — сборы с неё идут под этот проект (`data/lfg-setup.json`).
- **LFG → 🎭 Classes**: какие роли считаются классами и их иконки (эмодзи или эмодзи сервера `<:name:id>`).
  В посте показывается только иконка, после ника: `@игрок 🛡️ Персонаж`.
- Заметка к персонажу больше не показывается в посте — её видит только сам игрок при выборе персонажа.
- **Дубли поста**: админ после публикации выбирает каналы («📢 Also post this group in…»), копии обновляются и удаляются вместе со сбором.
- **🔊 Voice room** создаётся только если включить её при создании сбора (кнопка в мастере /lfg, галочка на сайте).

### Инструкции

На каждой вкладке есть кнопка **❔ Guide**: что умеет модуль, как пользоваться в Discord и как на сайте.

### Класс и заметка персонажа

- После записи в сбор под ответом бота: меню **класс** (одна из ролей сервера, которые есть у игрока) и кнопка **заметка**.
- То же командами `/character class name role` и `/character note name text` (пусто = убрать), `/character list` показывает.
- В посте сбора рядом с ником — эмодзи роли (если у роли задан эмодзи-значок), иначе упоминание роли (цветное имя, без пинга);
  под ником — заметка. Сохраняется за персонажем (`data/character-info.json`) и обновляется во всех активных сборах.

### LFG на сайте

- **Create a group** — канал, активность (с пингом роли) или своё название, слоты и роли, дата/время (часовой пояс сервера)
  или без времени, ЛС участникам роли, «организатор занимает слот 1». Организатор — тот, кто вошёл на сайт.
- **Recurring groups** — расписание: дни недели, время начала, за сколько часов до начала публиковать, организатор,
  вкл/выкл. Бот проверяет раз в минуту. Если публикация не удалась (нет доступа к каналу), повторение пропускается,
  ошибка видна в таблице и в журнале. Хранится в `data/recurring-lfg.json`.
- **Состав сбора** — у каждого участника: ✏️ сменить персонажа, ⬇️ в резерв, ✖️ убрать; в резерве: ⬆️ в группу (с ЛС),
  ✏️, ✖️. Пост в Discord обновляется сразу.

### Журнал (раздел Log)

- Действия на сайте (кто, что, с какими данными), в Discord (создание/закрытие сборов, изменение состава, тикеты:
  открыт / одобрен / закрыт, принудительные закрытия через `/admin`) и автоматические (истёкшие сборы, повторяющиеся сборы).
- Фильтры: человек, модуль, поиск. Хранятся последние 5000 записей в `data/audit.json`.

### Настройки (раздел Settings)

- Часовой пояс сервера, через сколько часов удалять посты сборов, за сколько минут напоминать (0 — выключить).
- Пустое поле = значение из `appsettings.json`. Применяется сразу, LFG-панели перерисовываются
  (в тексте панели `{hours}` и `{reminder}`). Время удаления уже опубликованных сборов не меняется.
- Хранится в `data/settings.json`.

### Сообщения бота (раздел Posts)

- **Panels** — все известные боту панели (LFG / Tickets / Room controls): ссылка, обновить текущим текстом, удалить.
- **Bot messages in a channel** — последние 50–500 сообщений бота в выбранном канале с типом
  (панель, LFG-сбор, тикет, прочее). Удаление по одному или галочками.
- Удаление поста LFG-сбора закрывает сбор (как Force close). Удалённая панель забывается.
- Право выдаётся отдельно: **Posts**.

### Тексты панелей (раздел Panel texts)

- Пустое поле или текст по умолчанию = стандартный текст. **Reset to default** возвращает всё.
- В тексте LFG-панели `{hours}` — время автоудаления сборов, `{reminder}` — за сколько минут напоминание.
- Бот запоминает панели, опубликованные после обновления (через сайт, `/admin` или команды).
  Панели, опубликованные раньше, найди один раз кнопкой **Find posted panels**
  (проверяются последние 50 сообщений каждого канала).
- Хранится в `data/panels.json`.

## 1. Бесплатный домен (DuckDNS)

1. Зайди на <https://www.duckdns.org> и войди (через Discord, GitHub или Google).
2. В поле **sub domain** введи имя, например `greatness-bot`, нажми **add domain**.
3. В строке домена в поле **current ip** впиши **IP своего VPS** и нажми **update ip**.

Адрес панели будет `https://greatness-bot.duckdns.org`. IP у VPS постоянный, обновлять его не нужно.

Проверка с ПК (PowerShell): `nslookup greatness-bot.duckdns.org` должен вернуть IP сервера.

## 2. Discord Developer Portal

<https://discord.com/developers/applications> → **Greatness Bot** → **OAuth2**:

1. **Client Secret** → **Reset Secret** → скопируй (понадобится на шаге 4). Токен бота при этом не меняется.
2. **Redirects** → **Add Redirect** → `https://greatness-bot.duckdns.org/signin-discord` → **Save Changes**.

## 3. Порты 80 и 443

Caddy нужен доступ к портам **80** и **443** (на 80 Let's Encrypt проверяет домен, на 443 работает сайт).
Если в панели TENET есть файрвол — открой там TCP 80 и 443. `ufw` на сервере скрипт откроет сам.

## 4. Обновить бота и включить панель

```bash
# обновить бота из git (как обычно)
bash /opt/GrtnsBot/deploy/linux/server-build.sh

# один раз: Caddy + Client Secret + HTTPS
sudo bash /opt/GrtnsBot/deploy/linux/setup-web.sh
```

`setup-web.sh` спросит домен и Client Secret (ввод скрыт), поставит Caddy, пропишет домен,
откроет порты в `ufw`, перезапустит бота и покажет Redirect-адрес для Developer Portal.

Секрет хранится в `/etc/greatnessbot.env` (строка `Web__ClientSecret=…`), как и токен бота. В git его нет.

Открой `https://greatness-bot.duckdns.org` → **Login with Discord**.

## Проверка и проблемы

| Симптом | Что делать |
| --- | --- |
| Сайт не открывается | `systemctl status caddy`, `journalctl -u caddy -n 50`. Чаще всего закрыты порты 80/443 или домен не указывает на IP сервера |
| «Discord login is not configured» | Нет `Web__ClientSecret` в `/etc/greatnessbot.env` — запусти `setup-web.sh` ещё раз |
| Discord пишет `Invalid OAuth2 redirect_uri` | В Developer Portal → OAuth2 → Redirects нет точного адреса `https://<домен>/signin-discord` |
| После входа «No access» | У аккаунта нет доступа — владелец выдаёт его в разделе Access |
| Бот не стартует, в логе `address already in use` | Порт 5080 занят — поменяй `Web:Urls` в `appsettings.json` и порт в `/etc/caddy/Caddyfile` |

Панель изнутри сервера: `curl -I http://127.0.0.1:5080/` → `200 OK`.

## Запуск на своём ПК (для теста)

1. В Developer Portal добавь ещё один Redirect: `http://localhost:5080/signin-discord`.
2. В папке проекта: `dotnet user-secrets set "Web:ClientSecret" "<секрет>"`.
3. Запусти бота и открой <http://localhost:5080>.

Не запускай бота на ПК, пока он работает на сервере: два экземпляра с одним токеном конфликтуют.

## Безопасность

- Панель слушает только `127.0.0.1`, напрямую из интернета к ней не попасть — только через Caddy (HTTPS).
- Вход только через Discord, пускаются владелец и те, кому он выдал доступ (по разделам). Cookie: HttpOnly, Secure, SameSite=Lax, 7 дней.
- Изменяющие запросы требуют заголовок `X-Panel` (защита от CSRF), страница отдаётся со строгим CSP.
- Ключи cookie лежат в `/opt/greatnessbot/data/web-keys` — после перезапуска бота входить заново не нужно.
  Удалить папку = разлогинить всех.
